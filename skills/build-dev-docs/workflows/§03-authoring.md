# 编写与更新

## 执行

1. 按最小文档计划读取所选职责对应的模板和目标文件最新内容，保留未提交修改。
2. 从零建立使用已确认设计；已有项目提取使用调研证据；持续更新只改本次受影响内容。模板用于提醒职责，不原样复制占位符或强制项目采用统一标题。
3. 用户要求预览时展示完整内容或 Diff；存在会改变文档范围、公开契约或项目结构的未知选择时，说明差异和推荐方案后询问。否则按明确请求直接写入。
4. 按依赖顺序写入所选文件并检查引用和事实一致性。出现新的产品或架构决策时暂停该部分，不能用文档编写替用户做决定。

## 文档间一致性

- 从引用所在文档计算相对路径；只有目标文件实际存在时才创建链接。
- 分清已实现、已验证、已确认设计和待决定状态。静态代码存在不等于运行验证通过。
- 更新关键决策时保留原 ADR，并用新记录说明替代关系；不知道历史理由时如实标注，不用推测补写。
- ROADMAP 的完成标记必须对应 Definition of Done 的实际证据。
- 只在计划已纳入时同步 AGENT_BRIEF 或 CHANGELOG；没有实质变化时不追加日志。

## 可选 AGENTS.md 入口

只有用户明确要求为多份开发文档提供 Agent 导航时，才增加或更新一行相对引用，例如：

```markdown
项目状态与开发文档入口：@docs/AGENT_BRIEF.md
```

按 Brief 的实际路径调整，不重复追加，不整体重写 AGENTS.md，也不修改 CLAUDE.md。
