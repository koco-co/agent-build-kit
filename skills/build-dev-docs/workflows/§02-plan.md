# 最小文档计划

根据 `rules/documents.md` 盘点现有文档职责，只选择本次需求和证据支持的内容。在对话中用下表记录实际计划；不适用的职责不进入表格，也不创建占位文件：

| 文档职责 | 现有或目标路径 | 本次操作 | 需要它的依据 | 验收方式 |
| --- | --- | --- | --- | --- |
| 对应职责 | 沿用路径或最小新增路径 | 新建 / 更新 / 保留 | 用户目标、仓库事实或缺口 | 可复现检查 |

有依赖的文档按“契约与术语 → 架构与决策 → 工程流程 → 状态与风险”排序；没有依赖时直接处理，不为形式拆分批次。

`AGENT_BRIEF.md` 仅在多份文档需要导航或跨会话状态入口时纳入。`CHANGELOG.md` 仅在项目已有该机制或用户明确要求时纳入。只有用户明确要求提供导航时，才提出 AGENTS.md 的一行引用；项目已有入口惯例不构成修改授权，也不因使用本 Skill 自动创建 AGENTS.md。

用户明确要求建立、提取或更新文档且计划可由现状确定时直接进入编写。用户要求先看计划，或路径、文档职责、公开契约存在实质选择时，展示差异与推荐方案并只确认一次。确认前不创建文件或占位目录。
