# §01 研究目标仓库

## 目标

在写任何正文前整理可追溯的项目事实清单，并确认现有修改是否与本次任务重叠。

## 读取顺序

1. 确认目标根目录、Git 根目录、当前分支、工作区状态和已跟踪的符号链接。
2. 完整读取根目录及所有候选子树中的 `AGENTS.md`、`CLAUDE.md`；检查普通文件、符号链接、导入文件和潜在断链，确认项目指令的 `CLAUDE.md` 只包含 `@AGENTS.md`。
3. 读取 README、Manifest、包管理配置、任务脚本、CI、主要入口和已有开发文档。
4. 使用目录树和搜索定位语言、框架、工作区边界、生成物、测试位置及平台适配文件。
5. 对候选命令追溯到实际脚本或配置，不根据通用习惯猜测。

优先使用 `git status --short`、`git ls-files`、`find` 或 `rg --files`、`git diff -- AGENTS.md CLAUDE.md` 等只读检查。不要在研究阶段安装依赖或运行会改写仓库的工具。

## 项目事实清单

为拟写内容记录：

- 事实或规则；
- 仓库证据位置；
- 适用目录；
- 若写成命令，其验证状态；
- 若来自旧指令，保留、泛化、下沉或移除的理由。

对无法证实但会显著改变结果的信息，才向用户提问。安全、可从仓库确定的默认项直接形成预览，不把探索责任转给用户。

## 判断是否需要子目录指令

列出候选子目录，并按 `rules/content-admission.md` 的“何时添加子目录指令”逐一判断。没有独立差异时只保留根文件；有差异时，只补充不同于根文件的内容。

需要判断项目形态或内容粒度时，再按形态读取 `examples/library-or-cli.example.md`、`examples/application.example.md` 或 `examples/monorepo.example.md`；不要照搬示例中的固定章节。

## 完成标准

- 现有指令与用户未提交修改均已识别。
- 主要目录、真实命令、关键约定和验证入口均有证据。
- 所有拟建嵌套文件都有明确理由。
- 需要迁移或移除的平台专有内容没有遗漏。
