# §02 内容方案与必要预览

## 目标

形成最终文件内容和所有破坏性差异。用户要求先看方案，或存在无法由仓库事实决定的范围、语义和删除取舍时，先展示预览；明确的初始化、重构或修复请求不重复确认本地编辑。

## 必须展示

1. 项目理解：一句话定位、工作区边界、关键技术栈与本次问题。
2. 文件操作表：每个 `AGENTS.md` 和 `CLAUDE.md` 的新增、整体替换、删除、保留或导入文件动作。
3. 每个 `AGENTS.md` 的完整拟写正文；已有文件整体重构时标明“完整内容预览”。
4. 每个嵌套文件的必要性，以及为什么根文件不足。
5. 旧内容处置表：保留、泛化、下沉、移除及理由，特别列出平台专有规则。
6. 命令验证状态：计划实际运行与“来源已确认、运行未验证”的命令。
7. 验收方式、剩余风险和明确排除项。

使用 `templates/replacement-preview.template.md` 组织输出，但删除不适用的章节，不能用占位符代替真实内容。

## 确认条件

用户要求预览时，结尾只询问一个决策：是否按以上完整内容和文件操作写入。无法查明的选项会改变文件范围、规则语义或删除内容时，说明具体差异和推荐方案后询问。

没有上述情况时直接写入明确请求的范围。确认或实施请求都不授权提交、推送、发布或本地 Plugin 更新。

## 冲突处理

若目标文件存在未提交修改：

- 将差异纳入事实表和完整预览；
- 能明确融合时展示融合后的完整正文；
- 无法判断所有权或会覆盖未知意图时，说明冲突并等待用户决策。

“允许整体重构”不等于可以覆盖预览之外的并发工作。
