# §04 验证与交付

## 静态校验

从 Skill 目录运行：

```bash
python3 scripts/validate_agents_md.py /path/to/project --strict
```

脚本检查根文件、嵌套文件、长度预算、`CLAUDE.md` 的普通文件类型与精确导入；`--strict` 还检查每份 `AGENTS.md` 内的 Markdown 链接引用与占位符，不检查远程可达性或图片替代文本。符号链接目标仍需人工核对。超长提示不会因 `--strict` 变成失败；是否删减仍按内容需要判断。

## 项目验证

按预览中的证据运行安全、低成本且与修改相关的命令，例如文档链接检查、Manifest 校验或仓库现有测试。不要为了验证指令安装依赖、连接生产、发布或执行迁移。

未运行的命令写成“来源已确认、运行未验证”，注明来源和原因。静态读取只能证明命令存在，不能证明它在当前环境成功。

## 内容审查

逐项执行 `checklists/semantic-acceptance.md`。静态校验通过不代表内容简洁、事实完整或子目录安排合理；内容审查必须对照仓库证据和最终差异。

可安全使用真实 Claude Code、Codex 或 DeepSeek Harness 时，分别从根目录和一个嵌套目录启动新会话，确认指令已加载且目录范围正确。未做真实客户端检查时明确标为未验证，不以文件存在代替加载成功。

## 差异检查

- 变更只包含已确认的 `AGENTS.md` 与 `CLAUDE.md`。
- `CLAUDE.md` 在 Git 中是普通文件，内容精确为 `@AGENTS.md`。
- 没有占位符、绝对本地路径、失效链接或复制的双正文。
- 用户原有不相关改动未被覆盖。

## 结果与证据

先说明在哪些目录建立了指令、正文是否统一维护、验证是否通过，再给出文件链接和复现命令。

必须报告：

- 新增、整体替换、删除和导入的文件；
- 每个嵌套文件的存在理由；
- 旧平台专有规则如何泛化、保留或经确认移除；
- 实际执行的命令与结果，以及未运行命令的原因；
- 未做的真实客户端加载验证和其他无法完成的内容；
- 明确未创建的项目文档、lint、CI 或 harness。

不要把校验器 PASS 扩大为“项目完全正确”或“所有客户端已验收”。

## 后续动作

先判断本次是独立调用，还是由 `audit-agent-setup` 等上层 Skill 调用。

### 受控调用

不重复询问或执行 commit、push、发布、部署，以及 Claude Code、Codex、ZCode、Pi 或 DeepSeek Harness 的本地安装/Plugin 更新。向上层返回：

- 修改内容与文件操作；
- 完整正文的确认依据；
- 静态校验和真实命令的验证证据；
- 未验证项；
- 恢复条件，以及是否允许继续其他后续任务。

发现新的产品、架构、公开接口或范围决策时，返回上层暂停处理，不自行扩大任务。

### 独立调用

实现和验证结束后，只把当前仓库真正需要的 commit、push、Claude Code Plugin 更新、Codex Plugin 更新、ZCode Plugin 更新、Pi Package 更新列入一次确认，并允许逐项授权。确认 commit 不等于确认 push，确认一个客户端更新也不等于确认另一个。

用户暂不授权时，交付仍然完成；保留清晰的工作区状态和建议提交说明即可。
