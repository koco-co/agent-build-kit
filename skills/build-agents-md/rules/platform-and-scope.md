# 平台与目录范围

## 一份正文，多个入口

- 每个目录范围的项目指令统一维护在 `AGENTS.md`。
- 同目录 `CLAUDE.md` 必须是普通文件，内容精确为 `@AGENTS.md`。
- 支持 `AGENTS.md` 的客户端直接读取该文件；Claude Code 通过同目录 `CLAUDE.md` 的 `@AGENTS.md` 导入同一正文。
- 其他客户端是否读取 `AGENTS.md` 或 `CLAUDE.md`，以该客户端文档为准，不在本 Skill 中推定。

普通文件类型与精确导入由 `validate_agents_md.py` 硬性检查；断链和占位符检查只在 `--strict` 下运行，且只覆盖每份 `AGENTS.md` 内的本地 Markdown 链接。符号链接目标、嵌套范围和旧内容迁移仍需人工核对。

## 旧内容迁移

读取已有 `CLAUDE.md` 后逐条处理：

1. 能跨平台表达的项目规则：改写为中立措辞后迁入 `AGENTS.md`。
2. 只与某个客户端机制有关、但不影响其他客户端使用的提示：写成带条件的平台说明。
3. 无法安全改写的内容：在完整预览中说明影响，请用户决定保留例外还是移除。

不得静默丢失平台专有行为，也不得把客户端全局配置误写成项目事实。

## 目录范围与优先级

根 `AGENTS.md` 描述全仓库共同事实。嵌套 `AGENTS.md` 只补充所在目录的差异；发生冲突时，明确子目录规则在该目录内覆盖根规则。

预览中为每个嵌套文件写出创建理由。理由消失时删除该嵌套文件及同目录 `CLAUDE.md`，不要留下重复或过期说明。

## 可以修改的文件

只修改用户明确请求或已确认位置的 `AGENTS.md` 与 `CLAUDE.md`。不得创建项目级 `docs/`、格式化器、lint、CI、测试 harness、安装脚本或示例工程。

研究发现这些体系缺失时，只列为现状或后续建议；没有额外授权，不把建议变成本次修改。

## 后续操作

写入指令不自动授权安装依赖、访问外部服务、提交、推送、发布或更新本地 Plugin。实现和验证完成后，统一询问一次当前项目真正需要的后续操作；用户只批准其中一项时，不推导其他授权。
