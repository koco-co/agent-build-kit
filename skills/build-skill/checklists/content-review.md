# 内容审查

检查 Skill 的正确性和完整性：是否忠实实现已确认需求。措辞润色不属于本清单；如果表达问题导致行为含义不确定，按内容问题处理。

## 需求与范围

- [ ] 每项行为、分支、兜底、兼容、校验、权限控制和提示词，都有用户需求、仓库事实、平台契约、可复现缺陷或明确安全要求作依据。
- [ ] Skill 解决的是用户的实际问题，不只是匹配请求中的关键词。
- [ ] 目标、非目标和完成标准彼此一致；每个目标都有对应行为或产物。
- [ ] 没有引入未确认的行为、权限或副作用。
- [ ] 已确认事实和未知项分开，推断没有进入实现依据。

## 路由与流程

- [ ] 已确认输入能进入对应分支，不属于本 Skill 的任务有退出方式。
- [ ] 步骤包含执行所需的条件、动作、结果和完成证据。
- [ ] 已知信息不重复询问，能自行查明的事实不转问用户。
- [ ] 已确认或可复现的失败、无法继续和取消场景有明确结果。
- [ ] 按需读取关系不会遗漏关键规则。
- [ ] 共享脚本的调用方、输入输出、失败契约、交付方式和验收命令完整一致；独立安装分支不依赖未随目标交付的 `.agents/scripts/`。
- [ ] 脚本运行时与任务匹配，偏离 Python 3.9+ 默认方案时有依据和可复现运行方式。

## Frontmatter 与平台

- [ ] Frontmatter 只包含必填、实际使用或用户指定审查的字段，每个可选字段都有真实需求和目标平台依据。
- [ ] 调用策略、正文触发语义和 Codex 适配彼此一致。
- [ ] `compatibility` 只描述硬性环境要求，没有要求时省略。
- [ ] 平台专属字段不会进入不支持它的安装副本。

## 安全与验证

- [ ] 限制措施对应真实的数据、权限、接口或外部副作用风险。
- [ ] 设计确认与执行、提交、推送、发布授权被明确区分。
- [ ] 静态检查、场景验证和真实平台验证没有互相替代。
- [ ] “已验证”都能追溯到命令、文件、测试或真实结果；未验证和阻塞内容已准确标记。

## 完成结果

- [ ] 内容正确、完整，达到可进入文案审查的状态。
- [ ] 剩余歧义已作为内容问题解决，没有留给文案审查猜测。
