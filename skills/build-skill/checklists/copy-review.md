# 文案审查

在内容审查通过后使用。目标是让指令自然、清楚、简洁、容易执行，读起来像一位严谨的中文作者写的，而不是翻译稿。文案修改不得改变行为、范围、权限、顺序或验收标准。

## 表达

- [ ] 中文自然，没有生硬翻译、抽象黑话和不必要的术语。
- [ ] 主语、动作、条件和结果清楚，不依赖隐含上下文猜测。
- [ ] 同一概念始终使用同一名称，不在不同文件里随意换词。
- [ ] 长句和密集段落按真实逻辑拆分，不机械分行。
- [ ] 一般行为用正向目标描述，明确禁止只留给安全和权限红线。

## 精简

- [ ] 没有重复 Frontmatter、平台配置、模板或其他规范源的内容。
- [ ] 没有解释模型已经能可靠推断的常识。
- [ ] 每句话都会改变理解、执行或验收结果。
- [ ] 说不清用途或依据的句子、状态、分支、文件和示例已删除。
- [ ] 标题直接说明章节用途，不生造概念。
- [ ] 示例值得模仿，没有玩具化、低信息量或占位内容。

## 语义保护

- [ ] 润色前后的触发条件、步骤顺序和完成条件一致。
- [ ] 没有弱化用户确认要求、权限边界和失败处理。
- [ ] 无法确定原意的句子已退回内容审查，没有自行补全含义。
- [ ] 文案修改后已重新执行内容回归和受影响测试。
