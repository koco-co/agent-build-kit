# Skill 架构规则

## 1. 最小结构

每个 Skill 至少包含 `SKILL.md`。其他目录只在有独立职责时创建，不要预建空目录或占位文件。

| 目录 | 职责 | 何时创建 |
| --- | --- | --- |
| `workflows/` | 较长阶段或独立分支 | 主流程放进 `SKILL.md` 会失去重点 |
| `rules/` | 跨工作流共享、需要判断的约束 | 规则无法由脚本可靠执行 |
| `templates/` | 固定字段或版式的空白产物 | 输出结构稳定且需要复用 |
| `examples/` | 可模仿的完整成品 | 风格、粒度或边界需要示范 |
| `checklists/` | 内容、文案、场景等人工审查 | 无法用脚本可靠判断 |
| `scripts/` | 格式化、转换、机械校验 | 处理是确定性的，且仓库没有可复用实现 |
| `prompts/` | Subagent 角色与返回协议 | 确实存在多 Agent 编排 |
| `references/` | 简单辅助资料 | 内容较少，不值得拆成专用目录 |
| `assets/` | 输出中复制或嵌入的静态资源 | 产物需要图片、样式或二进制文件 |
| `agents/` | 平台展示或调用策略 | 目标平台明确支持且确有需要 |

## 2. `SKILL.md` 的职责

`SKILL.md` 是入口，不是手册。它只回答四个问题：做什么、何时进入、按什么顺序做、哪些边界不能碰。详细步骤、字段表、长示例和平台差异放进附属文件，按需读取。

推荐结构：

| 章节 | 内容 |
| --- | --- |
| `# Outcome` | 一句话说明最终结果 |
| `## Routing` | 输入分支、排除条件和转交方式；没有分支时可并入 Steps |
| `## Steps` | 主流程；每步指向需要读取的文件 |
| `## Rules` | 必须始终遵守的边界 |
| `## References` | 附属文件索引，写清读取条件 |

不要为了“结构完整”保留空章节。`Delivery`、`Guardrails` 等内容只有在与 Steps、Rules 有实质区别时才单独成节；否则并入现有章节。入口建议控制在 500 行以内，超过时先删重复，再拆文件。

## 3. 工作流拆分

工作流使用 `§NN-name.md` 命名，按职责拆分，不按字数切分。一个文件内部可以用 `Phase 1` 至 `Phase N` 组织连续阶段；不要把同一职责拆成多个只有几行的文件。

## 4. 模板与示例

- 模板命名 `<artifact>.template.<extension>`，只放空白结构、必填字段和简短填写说明。
- 示例命名 `<artifact>.example.<extension>`，展示完成后的高质量结果。
- 同一内容只保留一种形态：模板负责“填什么”，示例负责“填成什么样”。

## 5. 脚本与清单

- 脚本处理可重复、可确定、能用退出码判断的检查；清单处理完整性、合理性、表达质量和场景覆盖。
- 已经由脚本保证的项目，不在清单里逐项重复。
- 脚本要有明确输入、输出、错误信息和非零失败退出码；优先提供 `--help` 或可读的用法说明。
- 优先复用仓库已有工具；没有可复用实现时，默认用 Python 3.9+ 编写并随 Skill 交付，避免第三方依赖。项目已有 Node、Shell 等统一约定时，跟随项目约定。

### 5.1 多 Skill 共享脚本

同时满足以下条件时，项目级 Skills 可以共用 `.agents/scripts/<script>`：

- 至少两个 Skills 已有真实调用需求，不为“以后可能复用”提前抽取；
- 脚本职责稳定，各调用方使用相同的输入、输出和失败契约；
- `.agents/scripts/` 会随项目或整体安装包交付，目标环境能够解析；
- 共享脚本是唯一规范源，各 Skill 只记录调用命令，不保存副本。

只被一个 Skill 使用，或独立安装、复制、发布时无法保证共享目录存在的脚本，放在该 Skill 的 `scripts/`。设计必须写明调用方、交付方式、运行环境和验收命令。

## 6. Subagent 与 References

- 不涉及 Subagent 时不创建 `prompts/`。
- 简单 Skill 可以只用 `references/`；内容变多后，再按职责移入 `rules/`、`workflows/` 等目录。
- `references/` 不能成为无法分类内容的堆放区。

## 7. 外部能力

以下能力通常应放在 Hooks、CI、CLI 或项目公共模块，而不是写进 Skill 提示词：

- 每次事件都必须自动执行的操作；
- 权限拦截与环境初始化；
- 与模型推理无关的固定转换；
- 多个 Skills 共用的稳定业务实现；
- 目标项目已经提供的校验或生成器。

设计必须说明这些能力的位置、触发时机、输入输出和授权边界。
