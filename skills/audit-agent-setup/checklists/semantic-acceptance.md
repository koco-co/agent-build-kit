# Audit Agent Setup 语义验收

## 范围与证据

- [ ] 只检查四个确认领域，没有扩张到代码质量、安全、依赖、测试覆盖率、CI 或性能。
- [ ] 每个适用性判断和问题都有仓库事实、平台契约、可复现缺陷或用户明确要求依据。
- [ ] Skill 审查覆盖最小充分原则；无法说明用途或重复规范源的内容会被具体报告。
- [ ] 检查新项目初始状态时，没有把暂时还不需要创建的文件或组件报为缺失问题。
- [ ] Plugin 或 Pi Package 内的 Skills 没有与独立 Agent Skill 领域重复报告。
- [ ] 没有 Skill、Plugin 或 Pi Package 时，只依据真实的重复工作或分发需要提出抽取建议。

## 交互与修复

- [ ] 检查阶段只读，首次输出是一次性报告。
- [ ] 每个问题都包含证据、修复方案、影响文件和验证方式。
- [ ] 没有发现问题时没有增加确认交互。
- [ ] 用户只要求检查时最多询问一次修复确认；已明确要求检查并修复时没有重复确认。
- [ ] 获得修复授权后直接把问题交给对应领域，没有要求用户选择内部 Skill。
- [ ] 新出现且会改变 README、项目指令、产品行为或公开契约的未决选择仍由所属领域说明并确认。

## 验证与交付

- [ ] 每个已授权修复都运行了承诺的领域校验。
- [ ] 修复后重新运行健康检查，并保留未授权问题。
- [ ] 静态检查、真实运行和未验证结论准确区分。
- [ ] 健康检查报告只留在对话中，没有另存为文件。
- [ ] 未经授权没有 commit、push、发布、部署或更新本地 Plugin。
