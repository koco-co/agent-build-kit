# 安全与权限规则

## 最小权限

Plugin 只声明完成目标所需的工具、网络、文件和服务权限。不要用宽泛权限掩盖不清楚的工作流。

## 用户确认

用户明确要求创建、升级或迁移 Plugin 时，该请求授权已说明范围内的本地文件写入。以下额外或高影响动作仍需明确授权：

- 删除请求范围外的用户文件；
- 执行需求未说明的稳定接口破坏；
- 提交、推送、发布或创建 Release；
- 安装依赖或修改全局环境；
- 启用网络、MCP、Hooks、遥测或持久化；
- 读取凭据、密钥或隐私数据；
- 提高权限或绕过沙箱。

## 数据流

每个 MCP、Hook 或外部服务都说明：

```text
读取什么
发送到哪里
为什么需要
保存多久
如何撤销
失败时如何处理
```

## 软链接

跨 Skill 运行依赖不使用软链接。对其他确需保留的链接，拒绝：

- 使用绝对路径的软链接；
- 越过 Plugin 或 Marketplace 边界的链接；
- 指向用户主目录、系统目录、凭据或临时敏感文件的链接；
- 失效链接和循环链接。

## 发布

真实发布前核对版本、变更说明、许可证、依赖、隐私说明和回滚方式；构建完成不等于允许发布。具体动作确认遵循 `workflows/§05-validation-delivery.md`，只列真实适用项并按用户明确授权执行。
