# 设计落实检查

比较“已确认设计”和“最终实现”，不替代静态校验。

## 目标与范围

- [ ] 每项行为、分支、兜底、兼容、校验、权限控制和提示词，都有用户需求、仓库事实、平台契约、可复现缺陷或明确安全要求作依据。
- [ ] 每个已确认目标都有对应实现或证据，每个非目标都没有被意外纳入。
- [ ] 变更没有越过用户确认的路径和行为范围。
- [ ] 提交、推送、发布和破坏性操作都有独立授权。

## 路由与流程

- [ ] 目标能用一句话说明最终结果。
- [ ] 每个独立输入都能路由到唯一分支，相邻任务有明确退出方式。
- [ ] 每个阶段都有完成条件；已确认或可复现的失败、无法继续和取消场景有明确结果。
- [ ] 用户只要求审查或预览、或仍有关键未决选择时保持只读；明确实施请求不重复确认本地编辑。

## 结构与职责

- [ ] 每个目录和文件都有单一、必要职责；没有空目录、空文件或占位内容。
- [ ] `SKILL.md` 只保留目标、路由、步骤和必要红线，细节按需读取。
- [ ] 模板、示例、规则、工作流之间没有重复职责。
- [ ] 能按确定规则执行的内容已交给 CLI、脚本或测试；事件级操作已放入 Hooks 或 CI。
- [ ] 项目级 Skill 复用项目已有能力，没有复制业务实现。
- [ ] `.agents/scripts/` 只在至少两个真实 Skill 共用、契约一致且目录随目标交付时使用；否则保持 Skill 自包含。
- [ ] 脚本运行时与任务匹配，并写明依赖和可复现命令。

## 平台与调用

- [ ] 核心工作流只有一个规范源。
- [ ] Frontmatter 只保留必填、实际使用或用户指定审查的字段，每个可选字段都有依据。
- [ ] 平台专属字段没有写进其他平台配置。
- [ ] 调用权限由平台配置控制；允许模型调用时，`description` 已写清触发和排除条件。
- [ ] `compatibility` 只写硬性环境要求，没有要求时省略。
- [ ] 安装路径、权限和依赖符合目标平台当前契约；无法等价适配的能力已明确处理。

## 验证

- [ ] 静态检查、内容审查、文案审查、内容回归和真实场景验证彼此分离。
- [ ] 重要变更已完成独立 Reviewer 审查；未完成时如实标记。
- [ ] 已确认行为、已声明契约和可复现缺陷有对应测试，没有为假想风险制造测试。
- [ ] 验证命令可复现，失败返回非零退出码。
- [ ] 未验证和无法完成的内容没有被描述为已通过。
